# The brief — 11.5, the seam

Teacher-only, and **deliberately not in the student folder** — same reason as the other two: an agent
that can read the brief answers the business instead of the learner.

This one is a **seam** between two things the learner has already specified and tested. The domain is
familiar on purpose, and — measured, see below — **almost every decision in it is inherited from the
learner's own 11.4 pricing specification.** That is the point of the step, not a defect: their earlier
text works as an asset, and a hole in it propagates into the new one.

## Calibrated 2026-08-18, and it killed two of the three forks I designed

Ran the brief through qwen2.5-coder 32b / 14b / 7b via the API, and through a frontier agent working in
an isolated folder. Verdict:

1. **"Which price does the admission check see?" is CLOSED BY THE SIGNATURE, not open.**
   `AdmissionPolicy.admits(duck: Duck)` receives a duck, never a price, so admission cannot see a
   running price without constructing a modified `Duck` — contrived enough that nobody proposed it.
   All three local models silently assumed shelf-price; the frontier named it a decision and argued it
   is *the only reading the signature supports*. Two independent lines of evidence. **Do not present
   this as a fork.** It is a place where a careful reader notices there is nothing to decide, which is
   worth something, but it is not ambiguity.
2. **"Whose condition is the gate?" was IMAGINARY.** Four readers out of four treated `OnlyIf` as a
   local filter on the duck and saw no conflict with the shop's policy — because there is none. The
   shop gates, the promotion filters, they do not compete. **Dropped.** Do not go looking for it in
   learners' work.
3. **"What does no-quote cover?" is alive but modest.** The frontier put "is a price of 0 allowed" to
   the business rather than deciding it; 7b decided the opposite way (`null` on a negative result). One
   genuine divergence.

**Consequence for the module, accepted 2026-08-18:** 11.5 does not need fork-richness, and demanding it
was an error of mine. Its content is the four steps *after* the specification — tests, agent, verify,
**refactor** — and the feature only has to be implementable. `quote` is, and it is small.

**One thing the calibration also caught:** a template titled `priceFor` handed out with a brief about
`quote`. Retitle the template for this step, or the first thing every learner reports is the mismatch.

**And one methodological failure worth not repeating:** the first frontier run was void because the
folder sat under `~/Downloads/kotlin_ai_strategy/`, two levels below `plan/content_plan.md` — which
spells out all three forks in our own words, with the 60/45 example. The agent cited a neighbouring file,
so it had walked up. Verifying "not inside a git repo" is not the same as verifying "nothing above this
describes the exercise".

`runAgent -Pmode=spec -Pbrief=briefs/11.5-seam.md` reads the business text from this file.

---

> Shops want to quote a price.
>
> - A shop already has a rule for who it lets in. A duck it will not take has no price.
> - A shop runs promotions — the same ones as before.
> - A customer wants one number: what does this cost here.
>
> Some promotions are meant for particular ducks rather than for everyone.
>
> Prices are whole units. The shop does not deal in fractions.

The surface to describe:

```kotlin
/** Returns what [shop] charges for [duck] under [promotions], or nothing if it will not take it. */
fun quote(duck: Duck, shop: Shop, promotions: List<DiscountRule>): Int?

data class Shop(val name: String, val admissionPolicy: AdmissionPolicy) {
    fun admits(duck: Duck): Boolean
}

fun interface AdmissionPolicy {
    fun admits(duck: Duck): Boolean
}
// leaves: KotlinOnly · MaxBudget(maxPrice) · RequiresAccessory(name) · MinAccessories(min)
// combinators: AllOf(policies) · AnyOf(policies) · Not(policy)

sealed interface DiscountRule {
    data class Percentage(val percent: Int) : DiscountRule
    data class AmountOff(val amount: Int) : DiscountRule
    data class BigSpenderBonus(val threshold: Int, val amount: Int) : DiscountRule
    data class Then(val first: DiscountRule, val second: DiscountRule) : DiscountRule
    data class BestOf(val options: List<DiscountRule>) : DiscountRule
    data class OnlyIf(val condition: AdmissionPolicy, val rule: DiscountRule) : DiscountRule
}
```

`Duck` is the type from before: `name`, `price`, `hasKotlinAttribute`, `accessories`.
